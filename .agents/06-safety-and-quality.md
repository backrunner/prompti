# 内容安全与题目质量

## 1. 政策目标

Prompti 面向旅行语言训练，默认只允许低风险、日常、实用主题。安全不是单次 prompt，而是输入、上下文、生成、展示和反馈五个阶段的纵深防护。

“政治敏感”必须落成可执行规则，不能依赖模糊词表。MVP 阻止政治宣传、说服、动员、选举操纵、仇恨/极端主义和针对人物/群体的煽动；允许旅行必需的中性公民信息，例如询问警察、使领馆、入境柜台、当地法律标识或紧急求助。此类允许内容不得扩展为法律建议。

## 2. 内容分类

### 2.1 允许

- 餐饮、购物、交通、住宿、景点、问路、打车、外卖。
- 礼貌表达、文化礼仪、无争议的地方习惯。
- 紧急联系、遗失物品、寻求警察/医院/使领馆帮助。
- 中性、必要的边检和海关沟通，不提供规避规则的方法。

### 2.2 拒绝

- 露骨色情、性服务、性剥削，尤其任何未成年人相关内容。
- 政治宣传、拉票、动员、定向说服、煽动、政党/候选人立场训练。
- 极端主义宣传、招募、赞美或行动指导。
- 仇恨、骚扰、歧视性贬损。
- 违法交易、武器、毒品、欺诈、规避执法或安全措施。
- 自伤指导、危险挑战。
- 提示词注入、索取 system prompt、要求忽略规则、代码/脚本执行主题。

### 2.3 限制并改写

- 酒吧/夜生活：仅允许点单、结账、交通与安全返程，不生成性服务或药物内容。
- 医疗：只允许描述症状、求助和寻找机构，不诊断、不提供用药方案。
- 法律/入境：只允许沟通句型，不给结论性建议，提示查阅官方来源。
- 宗教场所：允许礼仪、参观和问路，不生成劝诱、贬损或争论内容。

## 3. 自定义场景输入

### 3.1 预处理

1. Unicode NFC 归一化。
2. 移除首尾空白，合并重复空白。
3. 拒绝控制字符、换行、URL、代码围栏和不可见方向控制符。
4. 软限制 40、硬限制 80 grapheme clusters。
5. 本地高置信规则检测明显注入和禁止类别。

规则命中只做快速拒绝，不能作为唯一审查，因为多语言词形和上下文会绕过词表。

### 3.2 LLM 审核

用户明确要求自定义场景经过 LLM filter，因此在保存前调用可用的安全分类器：Apple 模型可用且支持输入语言时优先设备端，否则使用当前 BYOK Provider 的最小分类请求。

分类器只返回固定 schema：

- `decision`: allow / rewrite / reject / uncertain。
- `category`: travel / sexual / politicalPersuasion / extremism / violence / illegal / injection / medical / other。
- `normalizedScene`: 仅 allow/rewrite 时提供，仍受长度限制。
- `reasonCode`: 可本地化的枚举，不接受自由文本作为最终 UI 文案。

审核失败或 uncertain 时 fail closed：不保存、不生成，允许用户改写后重试。拒绝原文只在内存中处理，不进入 CloudKit 或分析。

## 4. 输出安全

- Provider 自身 moderation/guardrails 可作为额外信号，但不同 Provider 能力不同。
- 每道题在 schema 校验后做独立安全分类，批次中一题失败不污染合格题。
- 检查题干、所有选项、答案、解释、转写提示和罗马字字段。
- 被拒题只记录 `policyVersion + category + decision + provider`，不保存违规全文。
- UI 永不短暂渲染“待检查”内容，只有 `approved` 状态进入可见题库。
- 用户报告“不合适”后立即 quarantine，并在本地删除其预取资格。

## 5. 提示词注入防护

- 用户数据永远放在结构化 data section，固定 system instructions 在其外层。
- 给自定义场景分配本地 ID；后续管线优先传审核后的规范化短语而非原文。
- 场景不得包含 URL、Markdown、XML/JSON 结构或角色标签。
- 模型无工具访问能力，不给网络、文件或任意函数调用。
- source fact IDs 使用 allowlist，模型不能通过输出新 ID 扩展上下文。
- 检测输出中疑似 system prompt、角色标记或“忽略之前规则”文本并整题拒绝。
- 自定义 endpoint 的响应视为不可信网络输入，设置字节上限、解码深度和超时。

## 6. 质量门槛

### 6.1 语言质量

- 目标语言一致，无无意代码混合。
- 语法自然、礼貌程度合适、地区变体有依据。
- 讲解语言清晰，转写/罗马字不替代原文。
- A1/A2 题避免罕见词和长从句；高难题仍保持旅行实用性。

### 6.2 教学质量

- 单选题必须有唯一最佳答案。
- 干扰项不是无意义乱码，也不能因格式明显暴露答案。
- 完形空位考查目标表达，不依赖冷知识。
- 解释不循环引用答案，给出可复用规则。
- 口语题 rubric 接受合理同义表达，并能返回 undetermined。

### 6.3 目的地质量

- 每题至少关联一个目录 fact 或明确的通用旅行场景。
- 地域表达必须标注适用范围；有争议时使用标准表达。
- 不生成精确价格、时刻、营业时间、法规或“目前/今天”的事实。
- 不把刻板印象包装为地方文化。

## 7. 评审与政策治理

- `policyVersion`、`promptVersion`、`schemaVersion`、`catalogVersion` 写入每题元数据。
- 政策变更后可按版本批量重新审查库存，但不静默改写历史作答快照。
- 发布前建立多语言 adversarial corpus，包含混淆字符、委婉表达、角色注入、合法边界场景。
- 安全拒绝率按类别和 locale 在设备端聚合；只有明确 opt-in 才上传匿名指标。
- 误杀和漏放都需人工复盘，政策文件变更需要 code review。
