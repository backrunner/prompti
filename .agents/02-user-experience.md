# 用户体验与交互设计

## 1. 信息架构

MVP 使用四个顶层 Tab，设置从首页工具栏进入，避免五个以上入口造成拥挤。

| Tab | 主要内容 |
| --- | --- |
| 今日 | 当前目的地、连续打卡、快速开始、随机一题、库存状态 |
| 练习 | 目的地/语言/场景/难度/题量配置与练习会话 |
| 复习 | 错题集、历史题目、被跳过/报告题目 |
| 进度 | 每日完成、正确率、场景和语言分布 |

设置包含 AI Provider、iCloud、预生成、口语、显示/转写、隐私与开源许可。

## 2. 首次启动

### 2.1 页面顺序

1. **欢迎**：一句价值说明，不做营销式长页。
2. **选择目的地**：支持城市搜索和推荐目的地。
3. **选择语言**：只展示目的地声明的可训练 locale。
4. **选择 AI**：运行时能力检查后显示可用选项。
5. **测试配置**：连接、认证、模型、结构化输出能力和一次最小安全测试。
6. **训练偏好**：难度、默认题量、场景；预生成单独明确同意。

### 2.2 Apple 模型分支

| 状态 | UI 行为 |
| --- | --- |
| iOS 26+、模型 `.available`、支持目标 locale | Apple 设备端模型置顶并默认选中 |
| `.unavailable(.deviceNotEligible)` 或系统/地区不支持 | 隐藏 Apple 选项，BYOK 为必填 |
| `.unavailable(.modelNotReady)` | 显示“正在准备/尚未下载”，不可选；可稍后重试，当前需 BYOK |
| 模型可用但 `supportsLocale` 为 false | 说明该训练语言需要 BYOK，不把 Apple 作为当前语言选项 |
| 未知不可用原因 | 不暴露内部错误；提供重试和 BYOK 路径 |

模型能力会变化，因此每次切换语言、系统更新或模型状态变化后重新评估，不缓存成永久机型结论。

### 2.3 BYOK 表单

- Provider：自动识别、OpenAI Responses、OpenAI Chat、Anthropic Messages、OpenAI-compatible。
- Base URL：预置官方地址；只有自定义模式可编辑。
- API Key：SecureField，支持粘贴，永不回显完整值。
- Model ID：从可安全获取的模型列表选择或手动填写。
- 高级项：Organization/Project header、额外认证头；敏感值均进 Keychain。
- “测试连接”返回可操作结果：认证成功、模型存在、协议匹配、结构化输出可用性。

自动识别不是魔法。URL/模型名只能提供候选；自定义网关可能同时实现多种协议，最终以无害的最小握手测试为准，仍不确定时让用户选择。

## 3. 练习配置

配置采用一个可滚动页面，不把每个选项拆成多层卡片。

- 目的地：城市名为主标题，国家/地区作为次要信息。
- 目的地入口与列表使用各自独立、经审阅的当地地标 / 代表物 SVG，来源与生成流程按品牌规范记录。列表语言筛选及可练语言标签使用当前界面语言；未选中筛选不保留勾选空位，选中时平滑展开。筛选或搜索后列表回到顶部。
- 语言：菜单；显示本地名称与用户界面语言名称。
- 场景：可多选的紧凑列表，目的地特有场景单独分组。
- 自定义场景：sheet 中输入、字符计数、审核状态和拒绝原因。
- 难度：四段 segmented control；下方只显示一句对应说明。
- 题型：多选；若设备无麦克风权限，口语题保留但提示授权。
- 题量：stepper 或 picker；“随机一题”是独立快捷命令。
- 主操作：“生成并开始”。

## 4. 生成状态

生成不展示无法证明的 37% 一类精确百分比。采用可解释阶段：

1. 准备目的地内容。
2. 连接模型。
3. 生成练习。
4. 安全与质量检查。
5. 保存到题库。

页面必须始终提供取消。超过 8 秒后显示“可以离开此页，合格题目会保存”；这不表示 iOS 保证持续后台执行。应用进入后台后，当前网络请求可能完成，也可能被系统挂起。

### 4.1 部分成功

例如请求 10 题只得到 7 题合格时：

- 显示“7 题已准备好”。
- 主操作“先开始 7 题”。
- 次操作“继续补足”。
- 不向用户展示被安全或质量检查淘汰的原文。

### 4.2 错误文案原则

| 错误 | 用户行动 |
| --- | --- |
| 无网络/超时 | 重试；已保存题目仍可练习 |
| Key 无效 | 打开 Provider 设置 |
| 权限/余额/限流 | 查看 Provider 账户；稍后重试或换模型 |
| 模型不支持结构化输出 | 自动退化为 JSON + 严格本地校验，或换模型 |
| 内容连续不合格 | 调整场景/难度；不把原因归咎于用户 |
| Apple 模型不可用 | 展示系统原因；切换 BYOK |
| iCloud 不可用 | 继续本地保存；展示待同步状态 |

## 5. 作答体验

### 5.1 通用布局

- 顶部：`3 / 10`、场景、退出。
- 中央：题干、必要的目的地上下文、音频播放。
- 底部：答案控件和主操作；跳过位于次要工具菜单或清晰的次要按钮。
- 提交后原地展示结果，不跳转到新页面。
- 正确反馈短促轻快；错误反馈使用“再练一次”语气，不用惩罚色覆盖整个屏幕。

### 5.2 完形填空与选择题

- 选项使用固定高度、稳定布局，选中状态不改变卡片尺寸。
- 多空题逐空作答，答案顺序可打乱但必须保持稳定 identity。
- 解释包含：正确答案、自然译文、为什么其他干扰项不合适、一个可复用短语。

### 5.3 口语 QA

状态机：准备 -> 录音 -> 转写 -> 评估 -> 反馈。

- 首次录音前请求麦克风和语音识别权限，并解释用途。
- 允许先听题、重播、查看文字或隐藏文字。
- 反馈分为“表达清楚”“基本可理解”“建议重试”“无法判断”，并展示转写供用户纠正。
- 语义可接受答案可以有多种，不能只做字符串完全匹配。
- 若转写置信度低，结果为“无法判断”，不计错。

## 6. 跳过、报告与复习

- “跳过”直接进入下一题，可选原因但不强迫填写。
- “反馈题目问题”原因：答案不对、语言不自然、与目的地无关、内容不合适、其他。
- 报告后题目立即隔离，不再进入随机题和预取库存。
- 错题复习使用原题快照，保留当时的答案和解释；模型版本变化不能改写历史。
- 用户在复习中答对不会删除历史错误，只更新“最近答对”状态。

## 7. 视觉方向

完整实施规则见 [`13-brand-and-ui-guidelines.md`](13-brand-and-ui-guidelines.md)。Prompti 的气质是温暖、清晰、轻快而可信；品牌主体为 P 对话标识。

- 翡翠绿用于交互，薄荷与奶白用于品牌配对，暖中性色用于阅读；成功、警告、错误只表达对应状态。
- 品牌 Logo 使用生成器提供的矢量资源。城市、地标和场景图标承载旅行信息；不再用飞机作品牌、邮戳边框或多彩装饰。
- 圆角使用 14/20/24/32pt 层级；卡片、按钮、字体、间距使用 DesignSystem 共享实现。
- iOS 26 的 Liquid Glass 只用于 Tab、导航、工具栏和紧凑浮动控制；主按钮保持高对比实底，题目和统计使用不透明内容面。
- 动画服务于状态变化，支持 Reduce Motion；欢迎页以静态品牌与多语言问候表达交流。
- 纵向长列表按真实滚动位置显示上下渐隐遮罩，提示仍有内容；顶部、底部和短列表各自正确移除遮罩，不覆盖固定操作或拦截触控。
- 完成页只保留结果数值、短标题和非零统计；无可计分作答显示“— / 未计分”。整组题均答对显示“全部答对！”及一次 1.8 秒礼花，降低动态效果时保持静态。正确率仍按原口径计算；100% 的部分作答不视为整组全对。
- 功能图标使用 SF Symbols，品牌标识不使用 SF Symbols 替代；图标按钮提供无障碍标签。

## 8. 无障碍与本地化

- 所有正文支持最大 Dynamic Type，答案不能通过缩小字号硬塞。
- VoiceOver 朗读顺序：题号、场景、题干、选项、操作。
- 正误不能只依赖红绿颜色，还需图标与文字。
- 音频题始终提供文本替代；口语不是完成每日任务的唯一方式。
- 触控目标至少 44x44pt。
- 对日文假名、韩文、俄文可显示可关闭的罗马字/转写；转写不是答案本体。
- 从第一天使用 String Catalog，避免拼接句子，预留 RTL 布局能力。


## 2026-09-06：交互与视觉更新

- 首页主操作直接按默认偏好开始一组练习；“快速练一题”和“自定义练习”分别提供轻量入口与完整配置。待练题目只包含未作答题，点击即可开始；已作答题统一在复习中查看。
- 练习页优先展示目的地、语言、场景与题量，难度、题型、讲解语言收进“练习偏好”。提交、下一题、生成与完成操作固定在底部，阅读遮罩避免滚动内容穿透后与操作文字重叠。
- 模型连接在引导页和设置页复用同一组件。优先提供账号授权，可用 Apple 设备端模型仍优先默认选中；保留 API Key 接入。设置改动明确保存或取消，连接期间不允许切换待验证字段。
- 欢迎页原先采用飞机路线动画；该视觉方案已由 2026-09-07 的 P 对话品牌规范替代，交互步骤保持一致。
- iOS 26+ 原生玻璃保留在导航与紧凑浮动控件。2026-09-07 起内容区与主要按钮使用不透明表面；降低透明度和旧系统使用统一实色降级。

## 2026-09-06：验收范围确认

按用户明确要求，当前 UI 以系统默认字号和常规布局为验收范围，不要求非标准、超大字号等适配，也不将此类检查作为发布门槛。已有适配实现无需为此删除。
